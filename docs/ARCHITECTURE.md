## Почему FNO, а не PINN?

### Physics-Informed Neural Networks (PINN)

**Как работает PINN:**
- Нейросеть учится удовлетворять дифференциальным уравнениям
- Loss = MSE(граничные условия) + MSE(PDE residual)
- Не требует данных от симулятора — учится напрямую из уравнений

**Минусы PINN для нашей задачи:**

| Проблема | Описание |
|----------|----------|
| **Медленная инференция** | PINN решает PDE "с нуля" для каждого набора параметров. Нужно много итераций оптимизации (~10-100k). |
| **Плохо масштабируется** | Для сложных 2D/3D задач с множеством временных шагов PINN очень медленный |
| **Жесткие PDE** | Транспорт пропанта имеет резкие фронты и разрывы — PINN плохо справляется с такими решениями |
| **Параметрическая обобщаемость** | PINN нужно переобучать для каждого нового набора параметров |

### Fourier Neural Operator (FNO)

**Как работает FNO:**
- Учится отображать входные параметры → решение PDE за один forward pass
- Обучается на данных от численного солвера
- После обучения: мгновенная инференция (мс вместо секунд)

**Плюсы FNO для нашей задачи:**

| Преимущество | Описание |
|--------------|----------|
| **Мгновенная инференция** | ~10ms вместо ~5s (speedup 100-500x) |
| **Параметрическая обобщаемость** | Один раз обучили — работает для любых параметров из обучающего диапазона |
| **Разрешение-инвариантность** | FNO учит оператор, а не дискретную функцию — может работать на разных сетках |
| **Глобальные паттерны** | Fourier слои захватывают глобальную структуру решения |

**Минусы FNO:**

| Минус | Наше решение |
|-------|--------------|
| **Требует данные** | Генерируем датасет CPU солвером |
| **Спектральный bias** | Добавили Spectral Loss + увеличили modes |
| **Резкие фронты** | High-frequency weighting в loss функции |

### Сравнительная таблица

| Критерий | PINN | FNO | Выбор |
|----------|------|-----|-------|
| Инференция | ~10s | ~10ms | **FNO** |
| Обучение | Долго, нестабильно | Стандартное | **FNO** |
| Данные | Не нужны | Нужен датасет | — |
| Резкие фронты | Плохо | Средне (исправлено) | **FNO** |
| Физ. согласованность | Встроена | Нужна проверка | — |

**Вывод:** Для интерактивного симулятора где нужна быстрая инференция при варьировании параметров, **FNO — оптимальный выбор**.

## Физический солвер

### Уравнения двухфазного течения

**Сохранение массы пропанта:**
```
∂(cw)/∂t + ∇·(cw·Vₚ) = 0
```

**Закон Дарси для щели (Hele-Shaw):**
```
Vf = -w²/(12μ(c)) · (∇P - ρ(c)·g)
```

**Скорость пропанта:**
```
Vₚ = Vf + V_slip(c)
```

**Несжимаемость:**
```
∇·(Vf + c·V_slip) = 0
```

### Замыкающие соотношения

**Вязкость Krieger-Dougherty:**
```python
μ(c) = μ₀ · (1 - c/c_max)^(-β)
# β = 2.5, c_max = 0.635
```

**Плотность смеси:**
```python
ρ(c) = ρ_fluid·(1-c) + ρ_proppant·c
# ρ_fluid = 1000 kg/m³
# ρ_proppant = 2650 kg/m³
```

**Скорость оседания Richardson-Zaki:**
```python
V_stokes = 2/9 · (ρ_p - ρ_f) · g · r² / μ
V_slip = V_stokes · (1 - c/c_max)^n
# n ≈ 4.65 для сфер
```

### Численные методы

| Компонент | Метод |
|-----------|-------|
| Давление | Sparse direct solver / CG |
| Пространство | TVD (Koren/Superbee/Minmod) или WENO5 |
| Время | RK2/RK3 |
| CFL | Адаптивный шаг по времени |

### Структура CPU_solver


## Архитектура нейросети FNO

### Fourier Neural Operator — Концепция

FNO учит **оператор** G: параметры → решение PDE:
```
G: θ ∈ ℝⁿ → u(x,y,t) ∈ ℝ^(Nx×Ny×Nt)
```

### Ключевая идея: Spectral Convolution

Обычная свёртка работает в пространственной области:
```
(K * v)(x) = ∫ K(x-y)·v(y) dy
```

FNO работает в **частотной области**:
```
(K * v)(x) = F⁻¹(R · F(v))
```

где F — преобразование Фурье, R — обучаемые веса.

**Преимущества:**
- Глобальный receptive field за O(N log N)
- Естественное разделение частот
- Resolution invariance

### Архитектура FNOProppant

```
Input: params ∈ ℝ^9
       [c_inlet, Q_inlet, g, μ₀, r_particle, inlet_fraction, rk_stages, lim_type, injection_mode]
         ↓
┌─────────────────────────────────────────────────┐
│  Spatial Encoding                               │
│  params → expand to (batch, 9, nx, ny)          │
│  + coordinate grids (x, y)                      │
│  = (batch, 11, nx, ny)                          │
└─────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────┐
│  Lifting: Conv2d(11 → 64)                       │
│  Поднимаем размерность для обработки            │
└─────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────┐
│  FNO Blocks × 6                                 │
│  ┌─────────────────────────────────────────┐   │
│  │  SpectralConv2d (в частотной области)   │   │
│  │  + Linear Conv2d (локальные фичи)       │   │
│  │  + InstanceNorm + GELU                  │   │
│  └─────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────┐
│  Projection: Conv2d(64 → 128 → n_times)         │
│  + Sigmoid (концентрация ∈ [0, 1])              │
└─────────────────────────────────────────────────┘
         ↓
Output: trajectory ∈ ℝ^(batch, n_times, nx, ny)
```

### SpectralConv2d — Детали

```python
class SpectralConv2d:
    """
    2D свёртка в частотной области.

    Шаги:
    1. FFT: x → x_ft (переход в частотную область)
    2. Умножение на обучаемые веса: x_ft · W
    3. IFFT: обратно в пространственную область

    Truncation: храним только modes1 × modes2 нижних частот
    """

    def forward(x):
        # x: (batch, channels, nx, ny)

        # 1. Real FFT (используем симметрию)
        x_ft = torch.fft.rfft2(x)  # (batch, ch, nx, ny//2+1)

        # 2. Умножение на веса для нижних частот
        #    weights1: положительные частоты по x
        #    weights2: отрицательные частоты по x
        out_ft[:, :, :modes1, :modes2] = x_ft[:, :, :modes1, :modes2] @ weights1
        out_ft[:, :, -modes1:, :modes2] = x_ft[:, :, -modes1:, :modes2] @ weights2

        # 3. Inverse FFT
        return torch.fft.irfft2(out_ft)
```

### Гиперпараметры (после оптимизации)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| `modes1` | 24 | 75% от Nyquist (nx//2) — захват высоких частот |
| `modes2` | 12 | 75% от Nyquist (ny//2) |
| `width` | 64 | Богатые представления |
| `n_layers` | 6 | Глубокая иерархия фич |
| `n_params` | ~25M | Достаточно для сложной динамики |

### Проблема спектрального смещения и решение

**Проблема:** FNO учит низкие частоты намного лучше высоких.

**Причины:**
1. Truncation высоких мод в SpectralConv
2. L2 loss доминируется низкими частотами (больше энергии)
3. Градиенты для высоких частот маленькие

**Наше решение:**
1. ✅ Увеличили modes (12→24, 8→12)
2. ✅ Добавили SpectralLoss с весом для высоких частот
3. ✅ Увеличили width и depth

## Обучение и функции потерь

### CombinedLoss

```python
Loss = 0.7 · L_spatial + 0.3 · L_spectral
```

#### Relative L2 Loss (пространственная)

```python
L_spatial = ||pred - target||₂ / ||target||₂
```

**Преимущества:**
- Scale-invariant (не зависит от масштаба концентрации)
- Стандарт для PDE learning

#### Spectral Loss (частотная)

```python
def spectral_loss(pred, target):
    # FFT обоих тензоров
    pred_fft = torch.fft.rfft2(pred)
    target_fft = torch.fft.rfft2(target)

    # Ошибка в частотной области
    error = |pred_fft - target_fft|

    # Веса: больше для высоких частот
    freq_weight = 1 + (weight_high - 1) · normalized_frequency

    # Взвешенная ошибка
    return (error · freq_weight / |target_fft|).mean()
```

**Преимущества:**
- Явно штрафует ошибки на высоких частотах
- Помогает учить резкие фронты
- Основано на исследовании [arXiv:2511.08753]

### Training Pipeline

```python
Optimizer: AdamW (lr=1e-3, weight_decay=1e-4)

Scheduler:
  - Warmup: 5 эпох (линейный рост LR)
  - Cosine Annealing: плавное снижение до 1% от начального

Early Stopping:
  - patience=15 эпох без улучшения
  - min_delta=1e-4

Gradient Clipping: max_norm=1.0
```

### Метрика качества

```
Quality = (1 - Relative_L2_Loss) × 100%

Пример:
  Loss = 0.15 → Quality = 85%
  Loss = 0.30 → Quality = 70%
  Loss = 0.05 → Quality = 95%
```

## Генерация данных

### Latin Hypercube Sampling (LHS)

**Зачем:** Равномерное покрытие пространства параметров (лучше чем random).

```
Random Sampling:        LHS:
 ●  ●●                  ●     ●
    ●                      ●
  ●    ●                ●     ●
 ●●                        ●
```

**Алгоритм:**
1. Разбить [0,1] на N интервалов
2. В каждом интервале — ровно одна точка
3. Перемешать между измерениями

### Параметры датасета

| Параметр | Диапазон | Описание |
|----------|----------|----------|
| `c_inlet` | [0.15, 0.50] | Концентрация пропанта на входе |
| `Q_inlet` | [0.02, 0.10] m²/s | Расход жидкости |
| `g` | [0, 12] m/s² | Гравитация (0=горизонтальная, 9.81=вертикальная) |
| `mu0` | [0.5, 10] mPa·s | Вязкость жидкости |
| `r_particle` | [100, 500] μm | Радиус частиц |
| `inlet_fraction` | [1/6, 1/2] | Высота входной щели |

### Категориальные параметры

| Параметр | Варианты |
|----------|----------|
| `injection_mode` | continuous, single_pulse, multi_pulse |
| `lim_type` | koren, superbee, minmod |
| `rk_stages` | 2, 3 |

### Нормализация параметров

Все параметры нормализуются в [0, 1] перед подачей в FNO:

```python
params_normalized = [
    c_inlet / 0.5,
    Q_inlet / 0.1,
    g / 12.0,
    mu0 / 0.01,
    r_particle / 0.0005,
    inlet_fraction * 2,
    (rk_stages - 2) / 1.0,
    lim_type_idx / 2.0,
    injection_mode_idx / 2.0,
]
```
